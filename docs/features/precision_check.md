# Candidate-selection precision check

This CI gate measures whether the highest-ranked drug-disease pairs are valid repurposing
candidates. It scores live reports against committed human-reviewed labels. It does not assess the
correctness of report prose, evidence interpretation, or candidate cards.

## Scope

Labels exist for semaglutide, metformin, sildenafil, and bupropion; a run scores the drugs it is
given (`--drugs`), which the Makefile sets from `REGRESSION_DRUGS`. For each drug, it reads the five
highest-ranked diseases from the newest generated JSON report and compares them with the reviewed
label set.

The score is micro-averaged precision at five: the number of valid pairs divided by all scored pairs
across the scored drugs. CI passes at 90% or higher.

## Labels

`tests/regression/labels/candidate_precision.json` holds the reviewed drug-disease pairs, accepted
aliases, decisions, rationales, the rank cutoff, and the CI threshold. Matching uses exact equality
after lowercasing and trimming. Aliases must be listed explicitly.

A ranked pair without a label is not scored automatically. The check exits with a review-required
error so that a person can classify the new pair before CI proceeds. Duplicate labels, aliases,
reports, or ranked candidates also stop the check.

## Reports

The reports are generated by the live regression job and written under `test_reports/`. The check
selects the newest `<drug>_*.json` file by modification time for every drug named in the label set.
Missing reports and reports whose embedded drug name does not match the filename selection stop the
check.

The result is written to `results/precision/live_candidate_precision.md`. It contains the aggregate
precision, an approximate 95% Wilson interval, the CI threshold, per-drug results, and the report
filenames used for scoring. The file is uploaded as the `candidate-selection-precision` CI artifact
even when the gate fails.

## Labeling rubric

Candidate precision is measured over the candidates eligible to enter the investigation fan-out for each distinct drug
and historical cutoff. Each prediction is reviewed once for its drug, cutoff, and disease.

A candidate is **valid** when it is outside the drug's approved scope at the cutoff and independent evidence supports a
therapeutic hypothesis for that drug-disease pair. Evidence may include drug-specific clinical studies, consistent human
observational evidence, or a pharmacological mechanism supported by disease biology and evidence from the same drug class.

A candidate is **invalid** when it is already approved at the cutoff, represents only a broader parent or unrelated sibling
of the supported disease, describes an adverse effect or procedure rather than a therapeutic indication, conflicts with the
drug's pharmacological direction, or lacks an independent therapeutic rationale.

A candidate is **uncertain** when the available evidence cannot distinguish a defensible hypothesis from a false candidate.
Uncertain cases are not silently removed from the measurement.

Every decision records a reason category, a factual rationale, and the evidence used. Missing evidence produces an uncertain
decision, not a guessed label.

Reviewed precision divides valid decisions by valid plus invalid decisions. The report also gives a lower bound that counts
uncertain decisions as invalid and an upper bound that counts them as valid. Micro precision weights every prediction
equally. Macro precision gives each drug equal weight. A 95 percent Wilson interval accompanies the reviewed micro estimate.

The metric is precision at the configured investigation limit. It does not describe the full candidate universe beyond that
limit and it is not FDA-approval precision.

## Running

```text
make candidate-precision
```

This command expects a current JSON report in `test_reports/` for every drug in `REGRESSION_DRUGS`
(default: semaglutide and bupropion). To generate the reports and run all live regression checks, use:

```text
make regression
```

Live report generation requires an Anthropic key, a reachable PostgreSQL database with pgvector,
the embedding model, and access to the external biomedical data sources. The precision scorer
itself reads only the generated reports and committed labels.

## Updating labels

When a live report introduces a new top-five pair, review the drug-disease pair and add one label to
`candidate_precision.json`. Use `valid` only when the pair is a legitimate unapproved repurposing
candidate. Use `invalid` when it is already approved or is not a legitimate candidate. Record the
evidence basis in the rationale and add only aliases that refer to the same disease concept.

Run `make candidate-precision` again after updating the labels. Changing the cutoff or threshold is
done in the same label file and requires human review.

## Files

- `scripts/check_candidate_precision.py` selects and validates reports, runs the scorer, writes the
  result, and enforces the exit status.
- `src/indication_scout/services/precision_metrics.py` contains the validated data contracts,
  matching rules, precision calculation, Wilson interval, and report writer.
- `tests/regression/labels/candidate_precision.json` contains the reviewed labels and gate settings.
- `tests/unit/test_precision_metrics.py` covers scoring, aliases, invalid labels, and review-required
  failures.
- `.github/workflows/ci.yml` generates the live reports, runs the gate, and uploads the result.
