## What changed

### Layer 0 data-source contract tests (84112a9, c7d8329)

A new regression layer, `tests/regression/layer0_contracts/`, calls each data source client against a committed vcrpy cassette and
asserts the parsed Pydantic model field by field. Coverage: Open Targets `get_drug` and `get_target_data`, ClinicalTrials.gov
`get_trial`, PubMed `search` and `fetch_abstracts`, Europe PMC `fetch_citation_counts`, ChEMBL `get_molecule` and
`get_atc_description`, openFDA `get_label_indications` and `get_label_safety` (the two openFDA tests share one cassette). The
`conftest.py` fixtures hand each test an empty `tmp_path` cache directory so the call goes through the client parse path rather than
the file cache. A new `contract` pytest marker is registered in `pytest.ini` and is not excluded from a plain `pytest` run.
`docs/reference/testing.md` is new and describes the four kinds of test, re-recording with `SCOUT_CASSETTE_MODE=record`, and
drift-checking with `SCOUT_CASSETTE_MODE=live`; `README.md` and `tests/regression/README.md` point at it.

The shared cassette helper `tests/regression/common/cassette.py` gained two changes needed by this layer. `use_cassette` now
registers a custom `json_aware_body` matcher that normalizes a request body through `json.loads`/`json.dumps(sort_keys=True)`, which
replaces vcrpy's `body` matcher; aiohttp passes GraphQL POST bodies as an unserialized dict, on which the stock matcher raised. It
also takes a new `filter_query_parameters` argument, defaulting to empty, so PubMed and openFDA API keys carried in the query string
are scrubbed from recordings; the contract conftest passes `("api_key",)`.

In 84112a9 the contract tests ran inside `make test-regression`. c7d8329 moved them into their own `make test-contract` target, added
a matching CI step in `.github/workflows/ci.yml` before the offline regression step, and added the target to the `check` aggregate.

### Baricitinib regression pinning (9510c0f)

A new spec `tests/regression/specs/baricitinib.yaml` pins baricitinib invariants: psoriasis and systemic lupus erythematosus must
appear in the ranked list (order not pinned), the FDA-approved uses rheumatoid arthritis, alopecia areata and covid-19 must not,
twelve indications must stay in the candidate set, and specific NCT and PMID anchors plus a `black_box`/`serious` safety severity are
required for the two evidence-bearing indications. The commit also adds a gold-standard run artifact for
`baricitinib_2026-09-11_20-49-17` (JSON and rendered Markdown), not read at hunk level.

### Agentic retrieval shadow evaluation script (ae6f2cb)

`scripts/agentic_retrieval_eval.py` is a new standalone CLI comparing three arms — `baseline`, `oracle`, `agent` — for one bounded
extra literature search. The baseline and oracle arms drive the literature tools directly through `ainvoke` with synthetic
`ToolCall`s; the oracle additionally calls `search_additional_terms` with cohort-supplied disease terms, and the agent arm runs
`build_literature_agent`/`run_literature_agent`. It computes shortlist recall, cited recall, exact-pair precision, direction match and
an `unsupported_absence_claim` flag from phrase matching over the evidence summary, records per-case cost via `CostTracker`, and
writes an `EvalRun` JSON to `--output`. At run time it mutates two module globals in memory: it sets
`literature_tools.LITERATURE_EXTRA_SEARCH_BUDGET` to 1 and rewrites `literature_agent.SYSTEM_PROMPT` to say one call rather than two.
The script is not imported by production code and has no test.

### Exact-drug shortlist filter, added then reverted (ae6f2cb, c552361)

ae6f2cb added `_mentions_exact_drug(drug_names, item[0])` to the `baseline_scored` filter in `RetrievalService.semantic_search`
(`src/indication_scout/services/retrieval.py`), so papers naming none of the accepted drug names were dropped before the top-k slice
and lower-ranked eligible papers could backfill. It added `test_semantic_search_backfills_after_exact_drug_rejections` and rewrote
the abstract text in five existing `semantic_search` tests to contain a drug name so they still passed under the filter. c552361
reverts both the source change and the test changes exactly; `retrieval.py` and `tests/unit/services/test_retrieval.py` are back to
their state before ae6f2cb. The commit message gives no reason. `_mentions_exact_drug` is still called at `retrieval.py:178` in the
identity gate, so the revert leaves no dead code.
